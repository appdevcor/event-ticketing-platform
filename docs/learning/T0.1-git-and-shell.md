1- commands shell used so far 
    + mkdir : create a new directory
    + touch : create a new file 
    + git add : add updated files to index
    + git commit -m : save indexed files as an immutable snapshot with hash number in git history
    + git push -u origin branch-name : upload commited files to remote branch in github, the -u is required only for the first time to set link between origin and current branch
    + git pull : get all commits and merge them in local branch
    + git restore --staged file-path : pull out given file from index area 
    + cd : move to given path
    + ls : display all files and directories in given path 
    + cat : display the content of a given file with readonly mode
    + rm : remove definitely a given file path
    + mkdir -p : create directories and their parents if they are not created yet
    + <<EOF >> : add a given string in the end of file
    + git init : adding a hidden directory witch will contains all git history
    + git config : reading or setting git rules 
    + git status : show all updated files (staged, tracked or untracked) 
    + git log --oneline : show history of commits
    + git remote add : adding new remote / -v : read existing remotes with urls / set-url : setting url for existing remote
    + git check-ignore -v : check given file if will be ignored or not (0 ignored / 1 not ignored)
    + ssh-keygen : generating key pair
    + ssh-add : adding given ssh key to session
    + ssh -T : checking ssh connectivity 
    + docker run --rm hello-world : run a docker container and then remove it and its prouving that docker will run without sudo     

2 workflow from updating files to push 
    step 1 : updating files in the working tree
    step 2 : staging files with git add .
    step 3 : cheking files before commit with git status
    step 4 : commit files with git commit 
    step 5 : push to origin with git push origin branch-name

3 why .env file is never commited
    because this file contains a sensitive informations like keys, passwords ... should not be exposed in public repository
    .gitignore will not ignore a file if it was already tracked by git

4 
    working tree : is the working directory with all files 
    index : the staging area, contains all files was added by git add
    commit : creating a snapshot with indexed files in git history
