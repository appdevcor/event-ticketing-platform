# Revision sheet: T0.1 (shell, Git, SSH) and T0.2 (Git workflow)

## 1. The mental model: three zones

```
 working tree ──git add──▶ index (staging) ──git commit──▶ repository ──git push──▶ GitHub
 (your files               (the basket: what           (immutable snapshots,         (remote copy,
  as they are now)          the next commit will        the history)                  "origin")
                            contain)
```

- **Working tree**: your files on disk in their current state, including edits not yet added.
- **Index (staging area)**: the exact list of what goes into the next commit. It lets you commit only part of your changes.
- **Commit**: an immutable snapshot **of the index** (not of the working tree), identified by a hash. The branch pointer then moves to it.
- **Branch**: a pointer to a commit. `HEAD` points to the branch you are on.
- `git status` shows the three zones: "Changes to be committed" = index, "Changes not staged" and "Untracked files" = working tree.
- `git commit` with nothing staged creates nothing. With other files staged, it commits only those, so always run `git status` before committing.

## 2. Command cheat sheet

### Shell
| Command | What it does |
|---|---|
| `cd path` | Move to a directory |
| `ls` / `ls -a` | List files / include hidden files (`.git`, `.env`) |
| `cat file` | Print a file's content in the terminal (read-only) |
| `mkdir -p a/b/c` | Create a directory and missing parents, no error if it exists |
| `touch file` | Create an empty file |
| `rm file` | Delete **permanently** (no trash). `rm -rf dir` for directories |
| `>>` | Append to a file (`>` would overwrite it) |
| `<<EOF ... EOF` | Feed a multi-line block as input |

### Git
| Command | What it does |
|---|---|
| `git init -b main` | Create the repo (hidden `.git` folder holds the history) |
| `git config user.email ...` | Set a value; without `--global` it applies to this repo only |
| `git status` | State of the three zones |
| `git add file` | Put new or modified files into the index |
| `git commit -m "msg"` | Save the index as a snapshot |
| `git commit --amend --no-edit` | Fold a forgotten file into the last commit (**not yet pushed** only) |
| `git log --oneline` | Commit history reachable from the current branch |
| `git switch -c name` | Create a branch and move to it |
| `git push -u origin name` | Push; `-u` links the branch to the remote (first push only) |
| `git pull` | Fetch remote commits and merge them into the current branch |
| `git fetch --prune` | Update remote references and drop deleted remote branches |
| `git remote add / -v / set-url` | Add a remote / list remotes / change a remote URL |
| `git check-ignore -v file` | Show the `.gitignore` rule that matches. Without `-v`, exit code **0 = ignored, 1 = not ignored** |
| `git rm file` | Delete a file and stage the deletion |

### SSH and Docker
| Command | What it does |
|---|---|
| `ssh-keygen -t ed25519 -C "label" -f path` | Create a key pair. Private key never leaves your machine; give GitHub the `.pub` |
| `ssh-add path` | Load a key into the SSH agent |
| `ssh -T git@github.com` | Test the connection; "Hi <user>!" means the key is accepted |
| `docker run --rm hello-world` | Run a throwaway container; proves Docker works without `sudo` |

## 3. The daily workflow (trunk-based)

```bash
git switch main && git pull              # start from an up-to-date main
git switch -c type/short-description     # one short branch per task
# edit files
git status                               # check what changed
git add path/to/file
git commit -m "type(scope): description"
git push -u origin type/short-description
# GitHub: open PR, fill the template, read "Files changed", squash merge
git switch main && git pull && git fetch --prune
git branch -d type/short-description     # -D if Git refuses after a squash
```

**Why short branches and PRs, even solo:** `main` must always work (it will be deployed); a PR is a second look at your own diff and, from T0.10, the place where CI runs; the history stays readable.

**Conventions**
- Branch: `type/short-description` (types: `feat`, `fix`, `docs`, `build`, `test`, `ci`, `refactor`, `chore`).
- Commit and PR title: `type(scope): description`, imperative, lowercase. The PR title becomes the squash commit on `main`, so check it before confirming the merge.
- No direct commits to `main`. No secrets in Git.

### Merge methods
| Method | Result on `main` |
|---|---|
| Merge commit | All branch commits plus a merge commit |
| **Squash** (our choice) | One commit per PR. Easy to revert whole; you lose the fine granularity (`git bisect` cannot point at a small commit) |
| Rebase | Branch commits replayed one by one |

## 4. Undoing mistakes

| Situation | Command | Risk |
|---|---|---|
| Unstage a file | `git restore --staged file` | None, changes stay in the working tree |
| Discard edits to a file | `git restore file` | **Irreversible**: uncommitted edits are lost for good |
| Move `HEAD` back, keep everything | `git reset --soft HEAD~1` | None |
| Move `HEAD` back, unstage | `git reset --mixed HEAD~1` (default) | None, working tree kept |
| Move `HEAD` back, overwrite files | `git reset --hard HEAD~1` | **Overwrites tracked files' edits**; untracked files stay |
| Cancel an already **pushed** commit | `git revert <hash>` | Safe: adds a new commit, history is not rewritten |
| Find a "lost" commit | `git reflog`, then `git reset --hard <hash>` | See limits below |

**`git log` vs `git reflog`:** `log` shows commits reachable from the current branch. `reflog` is a **local** journal of everything `HEAD` did (commits, switches, resets, pulls), kept about 90 days (about 30 for unreachable commits).

**Limits of the reflog:** it is not pushed, so a fresh clone has almost nothing; it only knows **committed** work. Uncommitted changes destroyed by `restore` or `reset --hard` cannot be recovered. Rule: commit often on a working branch.

## 5. `.gitignore` and secrets

- Ignore: `.env`, `.env.*` (but keep `!.env.example`), `*.pem`, `*.key`, `*.ppk`, dumps (`*.sql`, `*.dump`), `vendor/`, `node_modules/`, editor folders, `*.log`.
- A typo in a pattern silently does nothing (`npde_modules/`), so **test rules** with `git check-ignore -v`. In `-v` mode negation rules are printed too, so use the exit code to know whether a file is really ignored.
- `.gitignore` only affects **untracked** files. A file committed once stays tracked.
- On a **public** repo, a secret that was ever committed is compromised, even if deleted later: it stays in the history. Rotate it.
- Always read `git status` (and the PR's "Files changed") before committing: it catches unexpected files.

## 6. SSH with several keys

- One key per use limits the damage if one leaks. Use a passphrase.
- `~/.ssh/config`, to bind the right key to GitHub:
  ```
  Host github.com
      HostName github.com
      User git
      IdentityFile ~/.ssh/id_ed25519_github_learning
      IdentitiesOnly yes
  ```
- Known issue: `agent refused operation` / `Permission denied (publickey)`. The desktop keyring agent holds the key but cannot ask for the passphrase from a terminal. Fix: `ssh-add -d <key>` then `ssh-add <key>`; durable fix: add `IdentityAgent none` to the `github.com` block (passphrase asked at each push).

## 7. GitHub settings used

- Pull requests: squash merging only; automatically delete head branches.
- Ruleset on `main`: enforcement **Active** (a disabled ruleset does nothing), target the default branch, restrict deletions, block force pushes, require a pull request with **0** approvals (you cannot approve your own PR), empty bypass list. Status checks are added in T0.10.
- Always **prove** a protection works: a direct `git push` to `main` must be rejected.
- The PR template is read from the **default branch**, so it only appears on PRs opened after it reached `main`.

## 8. Incidents seen, and the lesson

| Incident | Cause | Lesson |
|---|---|---|
| Remote URL looked wrong (`...platform..git`) | The GitHub repo name really ended with a dot | Verify with `git ls-remote origin` before "fixing"; avoid odd repo names |
| `agent refused operation` | Keyring agent cannot prompt for the passphrase | Section 6 |
| PR template missing on its own PR | Template is read from `main` | Section 7 |
| Squash commit with a non-conventional title | PR title left as generated from the branch name | Check the title in the squash dialog |
| `git pull` said "divergent branches" | A stray local commit on `main` plus a new remote commit | `git reset --hard origin/main` after checking what is dropped; set `git config pull.ff only` so divergence fails loudly |
| `test.txt` ended up in `main` | It was in the PR branch and the diff was not read | Read "Files changed" before merging; fix with a small PR (`git rm`) |
