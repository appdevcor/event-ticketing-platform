## 1. Git workflow
## 1.1 branch (git switch -c branch-name)
before starting implementation of new feature we start by creating a new branch, a new file created or existing file updated, indexing or committing will belong to this branch, the name convention for branch should start with type/name-of-feature
## 1.2 commit (git commit -m "your message here")
to save indexed files use git commit -m "your message", the commit is a snapshot of the index

## 1.3 push (git push -u origin branch-name)
creating the branch in remote with committed files 
## 1.4 PR
 a pull request proposes merging the pushed commits of a branch into main, for review
## 1.5 squash merge 
combine all commits of the branch into one, then merge

## 1.6 resynchronisation (git pull && git branch -d merged-branch)
switch to main and pull the code to update the local main repository then delete the branch  

## Why short branch
short branch keep controlling code changes easy, with short branch that contains a few changes you can review the code more efficiently

## squash and merge 
there is three type of merging a branch to main
    - merge commit : it save all commits in the branch and add one last commit of mixing all changes
    - squash commit : keep one commit that contains all changed files in all commits of branch
    - rebase : each commit is merged one by one
squash is the most optimised way to merge but if there is some issues in one commit all branch should be reverted 

## git restore --staged fileName used to popup a file or multiple files from index
## git restore fileName used to rollback all changes of a given file and not committed changes will also be lost

## git reset 
used to move the HEAD to given commit hash or from the commit parent if HEAD~1 is used
--soft move the HEAD step back only
--mixed move the HEAD step back and taking back files from index
--hard move the HEAD and delete all changes in tracked files from the working tree

## git revert used to take back a pushed commit without edit the history
## git reflog keep all HEAD actions tracked in journal for 90 days, ts a local journal and it can used to recover commits if there is any issues happened
